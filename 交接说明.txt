四、用户要求的最终操作逻辑
============================================================

1. 打开大 TXT 电子书不能长时间卡死。
2. 阅读过程中切换百分比不能卡死。
3. 正在朗读时按一次 Tab，焦点进入“阅读进度百分比”滑块。
4. 用左右方向键连续调整百分比，调整期间不能每 1% 就立即跳转或重启朗读。
5. 再按一次 Tab，跳到已经选好的百分比，并从该位置开始朗读。
6. Enter 和小键盘 Enter 也保留为确认百分比的按键。
7. 全局热键 Ctrl + Windows + Alt + F6：第一次真正停止书籍声音，第二次从暂停位置恢复。
8. 不影响语音参数设置、媒体键、书架、最近阅读和其他文档格式。

============================================================

核心文件：
  Source\bookworm\document\formats\plain_text.py
  Source\bookworm\reader.py
  Source\bookworm\gui\book_viewer\__init__.py

plain_text.py 当前参数：

实现：
1. 小 TXT 保持原有单页行为。

5. normalize_stored_position() 迁移旧版单页绝对位置。
6. 保留旧内容哈希和旧阅读位置兼容逻辑，不能删除。
7. 多页文档的百分比跳转直接计算目标逻辑页，不让 RichEdit 对全书做布局。

关键函数：

七、全局热键和真实音频暂停/恢复
============================================================

核心文件：
  Source\bookworm\text_to_speech\__init__.py
  Source\bookworm\platforms\win32\speech_engines\sapi\_sapi.py

当前用户配置：
  engine = sapi5
  voice = HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Speech\Voices\Tokens\AiSound_XiaoFeng

热键：
  Ctrl + Windows + Alt + F6

注册：
  wx.RegisterHotKey
  modifiers = wx.MOD_CONTROL | wx.MOD_ALT | wx.MOD_WIN | 0x4000
  0x4000 是 MOD_NOREPEAT，避免按住时快速反复切换。

问题历史：
1. 用户确认组合键确实触发，并听到“已暂停/已恢复”。
2. 2026.2.4 仅调用 SPVoice.Pause/Resume，小峰语音会忽略这些调用，因此书籍声音没有停止。
3. 旧音频流实现可以真正暂停，但恢复前依赖 GetStatus().State == Paused；第三方语音报告状态不可靠，导致“能暂停但恢复不了”。

2026.2.5/2026.2.6 最终实现：
  有 tts_audio_stream 时：
    暂停：tts_audio_stream.setState(SPAudioState.Paused, 0)
    恢复：tts_audio_stream.setState(SPAudioState.Running, 0)

恢复必须无条件设置 Running，不能根据旧 GetStatus 状态决定是否执行。
没有 tts_audio_stream 的语音才回退到 SPVoice.Pause/Resume。

SapiEventSink 的 StartStream/EndStream 在 paused 时不能覆盖 paused 状态。
speak_utterance 发出异步 Speak 后（当前不是 paused 时）主动设为 busy。

已使用当前小峰语音执行连续三轮底层音频流探测：
  每次暂停后状态 = 2（SPAudioState.Paused）
  每次恢复后状态 = 3（SPAudioState.Running）

关键测试：
  tests\test_sapi_pause_resume.py
  tests\test_text_to_speech.py

重要：桌面自动化安全规则禁止自动发送 Windows 键组合，因此最终必须让用户人工听声验收。不能把“已暂停/已恢复”的屏幕阅读器提示当成声音真的停止。

人工验收步骤：
1. 打开真实测试书并开始朗读。
2. 按 Ctrl+Win+Alt+F6，书籍声音必须立即停止。
3. 完整松开四个键。
4. 再按一次，必须继续朗读。
5. 连续做 3 至 5 轮。

如果仍失败，记录以下信息：
  on_global_pause_hotkey 是否到达
  engine.state 前后值
  ISpAudio GetStatus().State 前后值
  setState(Paused/Running) 是否抛出 COMError
  当前 voice token

八、2026.2.5 的“Failed to start Bookworm”退出错误及 2026.2.6 修复
============================================================

用户看到的信息：
  Failed to start Bookworm
  A fatal error has occured...
  C:\Users\apple007\bookworm.errors.log

实际发生时间在关闭程序时，不是启动时。日志堆栈：
  TextToSpeechService.shutdown
  stop_global_pause_hotkey
  self.view.Unbind
  RuntimeError: wrapped C/C++ object of type BookViewerWindow has been deleted

根因：
  wx 已先销毁 BookViewerWindow，服务退出清理仍尝试 Unbind/UnregisterHotKey，异常被启动器统一显示成“Failed to start”。

2026.2.6 修复：
1. stop_global_pause_hotkey 用 try/except RuntimeError/finally。
2. 窗口已经销毁时不再抛出致命错误；Windows 会自动释放销毁窗口拥有的热键。
3. 无论窗口状态如何，finally 都把 _global_pause_hotkey_registered 设为 False。
4. 新增 test_global_pause_shutdown_tolerates_destroyed_window。

实际安装后验证：
  2026.2.6 启动成功。
  使用 Alt+F4 正常关闭。
  C:\Users\apple007\bookworm.errors.log 的大小和修改时间没有变化。
  最新应用日志包含：
    Book viewer was already destroyed while removing hotkey.
    The application has exited gracefully.
